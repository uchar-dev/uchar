# Catala-states als sugar over gekoppelde attributen

Goal: Catala's benoemde stappen op één variabele (state bruto, state
na_aftrek, ...) lowert de plugin als zuivere sugar: elke stap wordt
een gewoon intern attribuut met eigen default-boom, stap n leest
stap n-1 — geen nieuwe knoop, mangling op het vars-tabelpunt,
downstream ongewijzigd (conform de verkenning van 2026-08-24 en
CONSTRUCTS rij 2's bestaande notitie). De bestaande
multistate-weigering versmalt tot wat werkelijk buiten het fragment
valt. E2E-fixture(s) door verifier+ref+clingo (verwachtingen geijkt
tegen catala interpret op /tmp-kopieën) plus een eigen catala-golden
met bron.catala_en byte-identiek onder gate 9.

Acceptance: rood-eerst (de huidige refusal letterlijk); alle negen
gates groen; twee opus-lenzen verwerkt vóór de merge.

May touch: frontends/catala/, corpus/golden/ (de nieuwe
catala-golden), scripts/check-noop.sh (alleen indien nodig),
backlog/. GEEN spec/CONSTRUCTS.md (registry serieel bij de landing).
Out of scope: ref/, backends/, alle normatieve spec-documenten,
spec/verifier/.

---

## Afgerond (2026-08-24)

Catala's `state`-stappen op één scope-variabele landen nu als suiker
over gekoppelde toekenning. De verkenning bevestigde empirisch dat
scopelang elke stap collapsed tot een eigen variabele `base#state`
(stap n leest stap n-1 via gewone variabele-referentie), en dat élke
door Catala geaccepteerde states-vorm binnen één scope een
per-stap-default-boom oplevert die de bestaande machinerie al aankan:
een uitzondering op een stap wordt gewoon een ladder op dat attribuut
(getest), een expliciete verwijzing naar een eerdere state weigert
Catala zelf, en een variabele-exceptie zonder state-kwalificatie idem.

De wijziging is chirurgisch, op het vars-tabelpunt in
`frontends/catala/lib/translate.ml`: de blanket-`#`-weigering is
vervangen door één helper `state_attr_name` die `#` naar een spatie
mangelt (`heffing#basis` → `heffing basis`), zodat elke stap een
gewoon intern attribuut met eigen default-boom wordt en alle
downstream-reads ongewijzigd via `lookup` resolven. Een base zónder
states heeft geen `#` en gaat verbatim door — byte-identiteit voor de
zeven bestaande catala-goldens (gate 9 bevestigt).

De multistate-weigering is versmald tot wat werkelijk buiten het
fragment valt: een subscope die een **multi-state output** van de
callee leest (het output-structveld draagt de kale basisnaam, maar de
states lowerden naar aparte attributen — er is geen enkel
output-attribuut om aan te binden). `refuse_subscope_multistate`
wijst nu die echte caller/callee-vorm luid af (needle "multi-state",
exit 3) in plaats van de oude standalone-keten die nu juist landt.
Detectie via `callee_multistate` (per scope de `#`-basisnamen),
gethread als functie-argument in de trant van `top_rung_vars`.

ROOD-EERST vastgelegd: de oude plugin op een kale states-bron gaf
letterlijk `refused: multi-state variable "heffing#basis": states are
out of scope … refused` (exit 3); na de wijziging vertaalt diezelfde
bron schoon (exit 0, verifier PASS).

Fixtures (verwachtingen geijkt tegen `catala interpret` op
/tmp-kopieën):
- `frontends/catala/test/states.catala_en` — een 3-stapsketen
  (bruto → na_aftrek → definitief) met een uitzondering op de laatste
  stap; twee cases pinnen de kale keten én beide exceptie-takken
  (verhoogd=false → 180 via de base, true → 95 via de topsport) door
  verifier + ref + clingo.
- eigen Jutterswet-golden `corpus/golden/jutterswet-vangstheffing-catala`
  (art. 11, getrapte vangstheffing over geld) — `bron.catala_en`
  byte-identiek geregenereerd onder gate 9; twee cases ($93.00 normaal,
  $125.00 grootvangst) door gates 2–8; de no-op-poort weigert beide
  (geen survivor-pin, dus `check-noop.sh` ongewijzigd).

Alle negen gates groen. `spec/CONSTRUCTS.md` bewust NIET geraakt
(registry serieel bij de landing); rij 9 noemt `refuse_subscope_multistate`
al als "multi-`state` subscope variables" — precies wat de weigering nu
werkelijk vangt.

Open flank (niet in scope, faalt luid indien ooit geraakt):
`ruled_vnames_of` mangelt niet, dus een multi-scope-programma waarin
twee scopes dezelfde states-variabelenaam definiëren zou de
kruis-scope-ambiguïteit missen en op WF-020 stuiten in plaats van
netjes te kwalificeren — geen enkele fixture raakt dit, en het faalt
luid, niet stil. **Gedicht in de lensronde hieronder.**

## Lensronde (2026-08-24)

Twee opus-lenzen verwerkt. BEVINDING 1 [MINOR/CONFIRMED] — de
hierboven genoemde open flank — eerst empirisch bevestigd, daarna
gedicht.

ROOD-EERST (letterlijk): een 2-scope-bron waarin `Eerste` en `Tweede`
allebei `output heffing … state bruto state netto` declareren vertaalde
schoon (plugin exit 0) maar de verifier viel op de collisie:

```
WF-020 FAIL /resolvedRegels/2: duplicate rule name 'berekening heffing bruto' in resolvedRegels
WF-020 FAIL /resolvedRegels/3: duplicate rule name 'berekening heffing netto' in resolvedRegels
WF-020 FAIL /resolvedRegels/0: form 'berekening heffing bruto' in resolvedRegels mixes a bare name with versioned entries
WF-020 FAIL /resolvedRegels/1: form 'berekening heffing netto' in resolvedRegels mixes a bare name with versioned entries
WF-021 FAIL /resolvedRegels/0: validity windows of versions 'berekening heffing bruto' and 'berekening heffing bruto' overlap (resolvedRegels)
WF-021 FAIL /resolvedRegels/1: validity windows of versions 'berekening heffing netto' and 'berekening heffing netto' overlap (resolvedRegels)
```

Wortel: `ruled_vnames_of` registreerde de ONGEMANGELDE scopelang-naam
(`heffing#bruto`) in `ambiguous`, terwijl `rule_label` de GEMANGELDE
naam (`heffing bruto`, via `state_attr_name`) toetst — dus
`List.mem vname ambiguous` was voor state-variabelen altijd false en
de subject-kwalificatie vuurde nooit. Eén-regelfix: `state_attr_name`
óók toepassen in `ruled_vnames_of`, zodat de detector precies
mangelt zoals de labeller (commentaar bijgewerkt). Na de fix
kwalificeren de regels netjes (`berekening Eerste heffing netto` vs
`berekening Tweede heffing netto`) en vertaalt diezelfde bron schoon
(verifier PASS).

Regressie vastgepind: `frontends/catala/test/states_twoscope.catala_en`
plus `cases/states_twoscope.json` — twee scopes met dezelfde
states-variabele, één case ($100 → 90 voor `Eerste`, → 80 voor
`Tweede`, geijkt tegen `catala interpret --no-stdlib` via
wrapper-scopes) door de volledige differentiaal (verifier + ref +
clingo) in de gate-9-suite.

BEVINDING 2 was er niet (één lens leverde één bevinding); de tweede
lensblik vond niets bovenop deze. Alle negen gates opnieuw groen.
