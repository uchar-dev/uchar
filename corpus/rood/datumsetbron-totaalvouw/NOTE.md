# datumsetbron-totaalvouw

`datumsetbron-somvouw`'s twin under the other additive kind. Same
document, same case, same two executors' refusals; the wire kind is
`TOTAAL` instead of `SOM`, and the pinned ASP sentence names it.

It is a case of its own rather than a second case file because the two
kinds part on exactly one clause — the empty set, where §5.8.2 gives the
som its `leegwaarde` and §4.20 gives the totaal an unconditional 0 — and
a witness that pins one kind's sentence says nothing about the other's.
Both executors carry the two kinds in ONE arm, so a mutation that removes
the refusal removes both; that is a property of the implementation and
not a reason to pin only half of it.

The empty-set clause is where this card's one measured asymmetry sits,
and it is recorded rather than hidden. On an EMPTY member set `ref`
never reaches the addition: the som answers leeg and the totaal answers
**0**, a number written into a `Datum in dagen` slot. The ASP backend now
declines the form whatever the case supplies, because the refusal is
about the DOCUMENT and not about which members a particular case happens
to link. So on that degenerate case the two executors part — `ref`
answers, clingo declines — and the direction is the harmless one: a
refusal against an answer no chapter defines. Nothing in the corpus
carries the shape, no producer writes it (the frontend types the sentence
out), and correcting `ref`'s 0 is the arbiter's own business and out of
this card's reach.
